## Ranked action 1: inspect cardinality-triggered macro before interpreting the composition trial

**High-confidence static interaction; map-specific occurrence and outcome effect unmeasured.**

`bots/v16s/src/bot.cpp` (same blob as v16o, `a4b5024`):
- L61–64 sets runtime team_size from allied champion handles, not draft picks.
- L111–112: runtime count >=4 forces pack_mode when non-monolith gem income exists, subject to the open-map override at L115.
- L160–170: runtime count >=4 enables a harmless-gold farmer; Issac is preferred when the safe-gold threshold is met.
- L190–196: squad count depends on pool size divided by POLARIS_MIN_SQUAD, and on pack mode and map size.
- L204–213 keeps Cassi and Issac together when allocating multiple squads.

The official [Cassi & Issac handbook](https://2026a.battlecode.co.uk/game/docs/cassi-and-issac), read fresh, confirms one draft choice creates **two separately acting units**, and **either dying kills both**. Both lose their carried gems; together they yield one kill reward. Thus a three-pick draft now produces four runtime units. Earlier shorthand “Cassi dies, so Issac dies” states only one direction; the actual risk is bidirectional.

A static counterexample: solo_gems>0, pack_gems=0, no open-map override. With 3 runtime units pack_mode is false; with 4 it becomes true. Separately, harmless-home-gold rate >=3 can enable an Issac farmer only in the four-unit case. These are code-expression examples, **not engine reproductions**, and do not prove that any particular public map changes mode. Expanse's geometric override may prevent the first interaction; a map already classified pack can also remain unchanged. Check actual maps before attributing 2/8 to this mechanism.

**Smallest experiment, with v16s otherwise fixed:**
1. Read/init-state fixture on collision, expanse, fragment and packs: record draft count, runtime count, pack_mode, farmer identity, squad membership and policy branch. Compare v16o/v16s. Do not require new replay decoding to print a one-time sanitized init summary.

Use a separate explicitly named policy count if justified; **never fake roster length or set team_size=3**, which could omit Issac from loops/shared-memory accounting.
3. Keep champion composition, purchases, combat, bank rules and risk model identical between A/B. Track early clears, productive champion-rounds, tribute pace, joint deaths and combined lost bags. Use all affected map/sides, not only the newly improved maps.

**Acceptance:** fixtures include all four real units exactly once, valid shared-memory ownership and correct linked-death handling. Any change must improve actual match wins/official tiebreaks repeatedly in Claude's paired external pipeline, not only r300 gems or body count. No fuel exhaustion or expanse regression. ## Ranked action 2: evaluate either member as a linked elimination target

**Confirmed mechanic + static score asymmetry; benefit is a hypothesis. Lower priority than action 1.**

combat() L508–525 explicitly says Cassi first because Issac dies with her. matchup() adds 140 for Cassi versus 40 for Issac. The 100-point difference may be useful because Cassi is a dangerous ranged carry, but the linked-death reward also applies to eliminating Issac. Do not treat the two units as independent kill rewards, or treat a Cassi-first bonus as universally optimal.

Concrete score example from the current formula (not a match):
- Both visible, in basic-attack range, unstunned, not channeling, carrying zero gems; attacker strength=100; no Varg splash.
- Cassi HP=500: score 60+140+120/(1+500/100)=220.
- Issac HP=120: score 60+40+120/(1+120/100)≈154.55.
- Current basic-attack proxy prefers Cassi, although absent intervening actions Issac needs two attacks versus five and either elimination removes both.
This is not a proof Issac is strategically better: range, damage returned, healing, shields, legal abilities, retreat and focus-fire coordination can reverse the choice. One-shot handling already supplies an extra bonus at L523, so this is **not** a claim the bot always ignores a lethal Issac.

**Smallest experiment:** only in an already-chosen fight with both duo members visible and already reachable, add a bounded two-target comparison for estimated legal time-to-disable and exposure; do not add chasing or change the engage/retreat gate. Use cached HP/range/ability readiness, with conservative unknowns. Preserve Cassi's threat contribution; do not simply equalize all champion bonuses. Candidate must be a new bots/ folder and chatgpt/ branch if implemented.

**Acceptance:** deterministic fixtures for one-shot Issac, two-hit Issac/healthy Cassi, shielded/healing Issac, out-of-range Issac and a more urgent channeling carrier; no increased pursuit radius and no hidden-state dependence. In paired matches report wins/tiebreaks first, then time to duo disable, allied bags lost and productive time gained; no fuel regressions. A kill-count increase alone does not qualify. This is distinct from rejected v16p/q/r's broader caution/fight-strength changes. No need to run this simultaneously with the composition/macro test.

Fullhouse transfer: use observable actions and confidence-shrunk estimates to value a decision, not “top teams do it” or a fixed identity label. A duo threatening us, retreating or hoarding a bag can require different responses. No cross-match learning or omniscient runtime fields proposed. MOBA macro/micro motivates keeping allocation and target selection separate; Sophia-style move ordering and bounded cached evaluation motivates testing two actionable targets rather than an unbounded fight search. These are inspirations, not measured performance claims.
