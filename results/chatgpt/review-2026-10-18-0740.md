In handle_enemies(), once the current fight-strength heuristic says favourable, the old code first handles in-range combat and selected kill/carrier chases. The new code then:
1. selects the nearest visible enemy satisfying Chebyshev distance <= enemy range+1;
2. calls move_to(enemy attack-radius disk);
3. calls combat(-1,true);
4. logs engage and **unconditionally returns true**.

The idea is plausible: continuing to farm while being poked can be costly. But range proximity does not show the enemy actually attacked, and favourable is computed before moving. ## Ranked action 1: make engage progress/failure explicit

**Confirmed control-flow concern; occurrence and match cost unmeasured. Highest priority.**

Source references in `bots/v16t/src/bot.cpp`:
- L865–867 ignores both move_to() and combat() return values.
- move_to(), L463–464, removes terrain/occupied goal tiles and can return false immediately. L497–498 also returns false if no move succeeds.
- combat(), L534, can return false with no candidate. Its action attempts also have failure/readiness paths.
- step(), L1002, returns immediately when handle_enemies() returns true. bank() is at L1003; capture/farm code is later.
- step() L994 skips wholly action-unready turns, but does not prevent a ready champion with blocked movement and no in-range attack from entering this case.

**Static counterexample:** after the earlier fight/chase predicates fail, favourable=true and an enemy satisfies range+1. If all approach goals are removed as blocked/unusable, move_to returns false; if no legal combat target/cast is available, combat returns false. handle_enemies nevertheless returns true. Under unchanged observations/blockage, this can repeat and suppress banking/capture/farming, despite no action.

The branch shape was checked logically: (move=false,combat=false) still returns true, exactly as for either success case. This was **not** a C++/engine fixture or observed match reproduction. Temporary cooldown waiting is not automatically a bug; repeated blocked action while alternatives exist is the case to distinguish.

**Correction to my preliminary commentary:** I initially referred to an old “farming stall guard”. Current v16t contains no such 12-round guard. The concrete supported problem is the unconditional early return before bank/capture/farm, not bypassing an existing guard. The generic stalled counter/soft movement penalty does not invalidate that return path.

The official [C++ API](https://2026a.battlecode.co.uk/game/api), champion methods, was checked fresh: can_move/can_attack/can_cast are separate state queries; move_absolute can return false for a newly revealed hidden obstruction and throw for known invalid destinations. The custom wrapper catches errors and reports failure. A requested action is not evidence that an action occurred.

**Smallest controlled experiment:**
- Keep draft, fight-strength, purchases, bank and target thresholds fixed.
- Add cheap local outcome flags for attempted target, move success, enemy action success, camp/support action success and repeated no-progress turns. Do not expand to an unprofiled map scan.
- Fixture cases: reachable ranged poke; blocked approach with no combat action; hidden obstruction; cooldown-only waiting; useful heal/shield; target disappears; winning bag near an altar.
- Only after reproducing meaningful repeated failure, test one candidate that handles that failure distinctly: bounded retarget/reposition or safe fallback, rather than claiming successful engage forever. **Do not simply return false and farm under lethal poke**, nor force a tribute through a dangerous enemy. Maintain the existing danger constraints.

combat(-1,true) also considers monsters and support actions, so even combat=true is not proof the selected enemy was engaged. Preserve productive support/camp actions without mislabelling them as an enemy hit.

**Acceptance:** the blocked/no-action fixture cannot consume unbounded consecutive turns when a legal alternative exists; cooldown/support cases remain correct; no new illegal action or shared-memory issue. ## Ranked action 2: test bounded anti-kite engagement only if productive-time evidence warrants it

**Hypothesis, lower priority; separate from failure handling.**

The new block lacks a per-target/episode pursuit budget, evidence of recent incoming damage, or a farm/bank opportunity-cost condition. A ranged opponent that repeatedly retreats can keep satisfying the range+1 trigger. Moving successfully every turn can still lose the farming race or postpone banking. This is a hypothesis about reachable behavior, not a route/playstyle inferred from final scores.

Because handle_enemies precedes bank(), the newly broadened nonlethal engage path can also defer a finish-capable bag. That ordering existed before, but v16t broadens which encounters consume it. Verify the opportunity cost before adding more aggression or more caution.

**Minimum experiment:** use the same v16t composition and fight/retreat gate. Compare only the new engage episode policy against a bounded version with a predeclared short horizon, resetting on genuine target/objective progress and exiting on lost vision or repeated non-progress. The exact horizon is a tuning parameter, not a known optimum. Distinguish enemy HP pressure, forced retreat/displacement and objective access from raw movement/kill count. Include a real damaging poker, a merely nearby non-attacker, a retreating kiter, an unreachable target and a safe finishing tribute alternative. Do not bundle the experiment with item, draft, danger-model or broader posture changes.

**Acceptance:** improved actual wins/tiebreaks with no increase in high-value bag losses; report captures/tributes and productive time gained or denied as mechanism metrics. Fewer deaths or more kills alone do not qualify. Preserve fog-of-war legality: vanished enemies become uncertain, not omniscient chase targets. Use cached positions with explicit age, O(1) episode state and a bounded action shortlist; measure release-Wasm fuel.

Fullhouse transfer: distinguish an aggressive opponent, a retreating bait and a hoarding carrier through observed behavior and uncertainty; do not substitute a rigid “nearby means attack” label. Sparse evidence should have bounded influence and shrink toward a conservative prior. This does not reopen the rejected full opponent-model package. MOBA macro motivates valuing farming/banking downtime; Sophia-style bounded search and empirical tuning motivates small explicit action budgets rather than indefinite pursuit. None is a claimed current-game performance gain.
